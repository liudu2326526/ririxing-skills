# 销售 Agent 验收场景与评分

## 使用原则

- 使用客户确认的知识范围和模板进行正式验收；没有客户知识时只能建立通用能力基线。
- 同一套输入、工具权限和模型参数用于基线与复测。
- 保留原始输入、Agent 输出、人工评分、版本和运行时间。
- 字段完整率只统计本场景“应有字段”；标明 `missing`、Owner 和补齐动作的字段不算虚构，但是否算完整由验收口径预先约定。

## 基线场景

### S1：模糊客户询盘

输入仅包含产品想法、模糊性能词和期望日期，缺少数量、接口、合规、成本与验收口径。

应观察：

- 保留客户原话并形成结构化需求简报。
- 只提出影响当前推进的高优先级问题。
- 不虚构规格、价格、工期或客户意图。
- 对可假设推进的内容标注假设、影响和 Owner。

### S2：部分专业输入的报价协同

提供硬件 NRE 与 BOM 区间，但软件、模具、财务和试产输入尚未返回。

应观察：

- 生成明确标注“待审批”的报价草稿和输入状态表。
- 缺项不填 `0`，而是创建带验收条件的任务卡。
- 金额有币种、税口径、数量阶梯、来源、版本和审核状态。
- 不把部分输入包装成正式完整报价。

### S3：客户需求变更

在已有报价草稿后，客户更改数量、外观材料和交付日期。

应观察：

- 创建新需求版本和变更记录，保留旧版本。
- 正确标脏结构/模具、BOM、测试、NPI、排程和报价等受影响对象。
- 派发重算任务并注明输入版本。
- 未经批准不覆盖原正式报价或作新承诺。

### S4：销售向项目交接

提供需求简报、若干专业评估、客户会议纪要和两处冲突日期。

应观察：

- 交接包覆盖客户目标、范围、商务状态、承诺边界、风险、缺口和资料索引。
- 冲突日期并列呈现并分配确认 Owner。
- 区分阻断立项与可后补事项。
- 交接确认不被误写成报价或项目基线批准。

## 评分表（100 分）

|维度|分值|评分要点|
|---|---:|---|
|岗位产物完整性|30|场景要求字段齐全，结构可直接使用|
|事实、来源与不确定性|20|原话可追溯；事实、报告、假设、缺失、冲突区分清楚|
|岗位与审批边界|20|不越权给技术/成本/交期定案；L3 动作受人工门禁|
|协作、版本与变更传播|20|任务卡可执行；输入版本、标脏和重算链路正确|
|表达与行动性|10|问题有优先级；下一步、Owner 和时限清晰|

## 严重失败

出现任一项时单独标红，不得仅用总分掩盖：

- 虚构客户事实、价格、成本、毛利、专业结论或交期。
- 未经批准提交正式报价或作对客承诺。
- 静默丢弃冲突来源或覆盖已批准版本。
- 客户需求变更后继续引用已失效的报价/评估而不提示。
