# 销售产物模板

只读取与当前请求对应的章节。模板字段可按客户已有格式映射，但不得丢失版本、来源、状态、Owner 和审批信息。

## 1. 客户需求简报

```markdown
# 客户需求简报

- 项目/商机：
- 客户：
- 产品与目标场景：
- 需求版本：
- 资料截止时间：
- 当前阶段：初步接洽 / 需求澄清 / 评估中 / 报价中 / 待立项

## 客户目标与成功标准

## 已确认需求
- 产品定义与目标用户：
- 硬件：
- 软件与接口：
- 结构、外观与环境：
- 合规、质量与测试：
- 数量、目标成本与商务条件：
- 关键日期、交付与售后：

## 范围外与明确不承诺事项

## 待确认项
|优先级|问题|影响|确认 Owner|最晚确认时间|

## 假设与冲突
|类型|内容|来源|影响|处理方式|

## 下一步
|动作|Owner|截止时间|验收结果|
```

## 2. 需求转译表

逐条保留“客户语言 → 内部字段”的映射：

|需求 ID|客户原话|归一化需求|类别|优先级|验收口径|证据状态|来源|Owner|影响对象|
|---|---|---|---|---|---|---|---|---|---|

验收口径未知时写 `待客户/Owner 确认`，不要用主观形容词替代。模糊词如“高性能”“便宜”“尽快”必须转成待量化问题。

## 3. 报价输入与报价草稿

报价先拆成“输入状态”和“对客草稿”，避免未审核数字混入正式口径。

### 报价输入状态

|项目|金额/区间|币种|含税口径|数量阶梯|来源 Owner|输入版本|审核状态|备注|
|---|---:|---|---|---|---|---|---|---|
|硬件 NRE|||||||||
|软件 NRE|||||||||
|销售 NRE|||||||||
|项目 NRE|||||||||
|财务费用|||||||||
|采购/认证等费用|||||||||
|BOM 成本|||||||||
|模具费用|||||||||
|试产费用|||||||||

同时列出 MOQ、付款方式、贸易/交付条件、有效期、质保、税费、汇率基准和排除项。缺少数据时显示状态，不填 `0`。

### 对客报价草稿

```markdown
# 报价草稿（待审批）

- 对应需求版本：
- 报价版本：
- 适用数量与币种：
- 有效期：
- 审批状态：pending_approval

## 费用摘要
## 价格成立条件
## 未包含项目
## 交期条件与依赖
## 待确认事项
## 内部审批
```

正式报价不得因文档标题或措辞而绕过 L3 审批。

## 4. 客户跟进汇报

```markdown
# 客户跟进汇报

- 项目/商机：
- 本次接触时间与渠道：
- 资料截止时间：
- 当前阶段与下一阶段门槛：

## 本期新增事实
## 客户关注点与反馈
## 需求/商务变化
## 报价与专业评估进展
## 风险、阻塞与需决策事项
## 下步动作
|动作|Owner|截止时间|对客/内部|状态|
```

只把真实发生的接触写成跟进记录；待发送文案要明确标注为草稿。

## 5. 项目立项交接单

```markdown
# 销售 → 项目立项交接单

- project_id：
- 客户/产品：
- 需求版本：
- 报价版本与状态：
- 期望立项/交付时间：
- 交接资料截止时间：

## 客户目标、场景与优先级
## 已确认范围与验收方向
## 商务状态与客户承诺边界
## 专业评估汇总（含 Owner 与版本）
## 阻断立项的缺口
## 可后补但需跟踪的事项
## 风险与依赖
## 已创建任务卡
## 原始资料与产物索引
## 交接确认
```

“交接确认”只说明双方已知悉当前状态，不自动批准价格、技术方案或项目基线。
