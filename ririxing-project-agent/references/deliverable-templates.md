# 项目产物模板

只读取与当前工作模式相符的章节。可以映射到客户现有模板，但保留项目标识、版本、状态、Owner、资料截止时间和审批信息。

## 1. 项目章程与立项检查

```markdown
# 项目章程（草稿/待审批）

- project_id：
- 客户/产品：
- 当前阶段：
- 对应需求版本：
- 对应报价/商务状态：
- 资料截止时间：
- 项目负责人/发起人：

## 目标与成功标准
## 范围内 / 范围外
## 关键交付物与验收方向
## 目标里程碑
## 治理、汇报与审批关系
## 关键假设与约束
## 初始风险与依赖
## 阻断立项的缺口
## 可后补事项及 Owner
## 立项审批
```

立项通过不自动批准技术方案、报价或详细排程，除非审批记录明确覆盖这些对象和版本。

## 2. 项目周期表

|WBS|阶段/工作包|Owner|输入版本|前置依赖|工期及来源|目标开始/完成|预测开始/完成|基线开始/完成|交付物与验收|状态|风险/备注|
|---|---|---|---|---|---|---|---|---|---|---|---|

表前说明：

- 工作日历、节假日和时区。
- 资源/产能约束与并行假设。
- 缓冲策略和关键路径。
- 当前计划状态与 `baseline_version`。
- 日期精度限制；未知输入用区间或场景表达。

## 3. 日报 / 周报

```markdown
# 项目日报/周报

- 项目：
- 报告周期：
- 数据截止时间：
- 需求版本 / baseline_version：
- 总体状态：绿 / 黄 / 红（附判定原因）

## 本期已验收完成
|交付物|Owner|完成时间|证据|

## 进行中与下一步
|任务|Owner|当前状态|下步动作|预测完成|

## 逾期与阻塞
|任务|基线/目标|当前预测|偏差|原因|恢复动作|Owner|

## 未来里程碑
|里程碑|基线日期|预测日期|置信度|前置条件|

## 风险与问题
## 需决策事项
|决策|选项/建议|决策人|最晚时间|不决策影响|

## 需求、成本或计划变更
## 数据缺口与新鲜度
```

总体颜色必须有明确阈值或事实依据。没有实际状态更新时，不把计划值复述成进展。

## 4. 里程碑预警

```markdown
# 里程碑预警

- 里程碑：
- 当前等级：提示 / 预警 / 升级
- 基线日期 / 当前预测：
- 偏差与触发阈值：
- 影响范围：范围 / 成本 / 周期 / 质量 / 客户
- 根因证据：
- 恢复方案与 Owner：
- 需决策事项、决策人和最晚时间：
- 下次复核时间：
```

预测跨过阈值时应主动预警；已发生的延期应登记为问题，不再只写“有风险”。

## 5. 风险与问题台账

|ID|类型|描述|概率|影响|触发器/已发生时间|Owner|缓解/处置|应急动作|截止时间|状态|关联任务/里程碑|
|---|---|---|---|---|---|---|---|---|---|---|---|

风险概率与影响可以使用客户既有等级；没有标准时先声明临时口径，不虚构精确概率。

```markdown
|角色|人员|结论|时间|覆盖版本|

```

审批前保留原基线。批准后创建新基线版本并通知所有受影响 Owner。

## 7. 收尾与归档检查

```markdown
# 项目收尾与归档检查

## 已验收交付物与证据
## 未结问题、责任人和后续时限
## 最终需求 / 报价 / 基线版本
## 关键决策与变更索引
## 风险关闭或移交
## 复盘：有效做法、偏差原因、可复用知识
## 归档位置、权限与完整性检查
## 客户/内部关闭审批
```

关闭项目不应删除未结事项；要明确移交对象并保留访问权限和审计记录。
